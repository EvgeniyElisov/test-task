# 01. Сопоставление заказов маркетплейса с выгрузкой 1С

## Запуск

Нужен PHP 8.1+ (без Composer).

```bash
cd 01
php match.php
php bugs/OrderTotal.php
```

Опции:

```bash
php match.php --orders=data/orders.json --nomenclature=data/nomenclature_1c.csv --out=output
```

Результат:
- `output/report.csv` — отчёт для менеджера (UTF-8 BOM, разделитель `;`)
- `output/sync.log` — ошибки и предупреждения по битым записям

Источник заказов сейчас — JSON-файл (`JsonFileOrdersSource`). Чтобы ходить в HTTP API, достаточно заменить реализацию `OrdersSource`.

## Решения по неоднозначностям

| Вопрос | Решение |
|--------|---------|
| Отменённые заказы (`cancelled`) | Не выгружаем в 1С, **не резервируем** остаток. В отчёте `SKIP`. |
| Дубль `id` заказа в ответе API | Берём **первое** вхождение, повтор — `SKIP` / `DUPLICATE_ORDER_ID`. |
| Остаток | Считаем **суммарно** по неотменённым заказам в порядке файла (FIFO). Иначе два заказа по 3 шт при остатке 4 оба «пройдут». Дубль `id` остаток не ест. Заказ с ошибкой цены тоже резервирует: после правки цены товар всё равно понадобится. |
| Частичная выгрузка | Если в заказе хоть одна плохая строка — **весь** заказ `BLOCKED`. В 1С не отправляем «хорошую половину». |
| Артикул | `trim` + сравнение без учёта регистра (`ts-1002` / ` TS-1002` → `TS-1002`). |
| Несколько карточек 1С на один артикул | `AMBIGUOUS_SKU`, заказ блокируем — автоматом не угадываем, какую карточку брать. |
| Допуск цены | расхождение > 0.009 BYN = `PRICE_MISMATCH`. |
| Пустой `items` / нет `price` | В лог + `BLOCKED` / `INVALID_ITEM`, скрипт не падает. |

## Коды в отчёте

- `OK` — можно передавать в 1С  
- `BLOCKED` — есть расхождения, нужна ручная правка  
- `SKIP` — отмена или дубль id  
- `ERROR` — сбой обработки записи  

Типичные issues: `SKU_NOT_IN_1C`, `PRICE_MISMATCH`, `INSUFFICIENT_STOCK`, `AMBIGUOUS_SKU`, `DUPLICATE_ORDER_ID`, `CANCELLED`, `EMPTY_ITEMS`, `INVALID_ITEM`.
